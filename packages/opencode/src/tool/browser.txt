Drive the shared session browser: one Chromium inside the container that the
human can also see and drive. Anything this tool does appears on the human's
screen, and anything they do is visible to you through a later snapshot.

Take a snapshot before acting. The snapshot returns the page's accessibility
tree as text, where every interactive element carries a ref like `@e3`:

  - button "Sign in" [ref=e2]
  - textbox "Email" [ref=e3]

Use those refs with `click`, `fill`, and the other element actions. Refs come
from the last snapshot and stop being valid when the page navigates, so take a
fresh snapshot after navigating, and again if a ref stops resolving.

Where an action takes a `target`, it accepts an `@ref` from the last snapshot or
a CSS selector. Prefer refs: they survive a small DOM change that would move a
selector.

Navigate
- navigate <url>: open a URL.
- back / forward / reload: history and reload, the same as the browser buttons.
- pushstate <url>: client-side navigation in a single-page app.

Read the page
- snapshot: the accessibility tree with refs. `full` returns every node; `selector` scopes it.
- read [url]: agent-readable text of the page.
- get <what> [selector]: text, html, value, attr <name>, title, url, count, box, styles.
- is <what> <target>: visible, enabled, checked. Check before acting on something that may not be there.
- find <locator> <value> <action>: locate by role, text, label, placeholder, alt, title, testid, first, last, or nth.
- console / errors: the page's console output and JavaScript errors. Read these when something fails.
- network: the requests the page made.
- vitals [url]: Core Web Vitals, when the page's performance matters.
- diff: changes since the last snapshot.

Act on the page
- click / dblclick <target>.
- fill <target> <text>: clear the field and type. `type` appends instead.
- press <key>: Enter, Tab, Control+a.
- keyboard <text>: type into whatever has focus, with real keystrokes.
- hover / focus <target>.
- check / uncheck <target>: for checkboxes and radios.
- select <target> <value>: pick a dropdown option by value or visible label.
- scroll <direction> [px], scrollintoview <target>.
- drag <target> <into>.
- upload <target> <path>, download <target> <path>.

Wait
- wait <target>: wait for a selector to appear.
- waitms <ms>: wait a fixed number of milliseconds.

The page is live and the agent races it, so wait rather than retrying in a loop.

Tabs
- tabnew [url] / tablist / tabselect <id>: the human may have several tabs open.
There is no way to close a tab from here.

Capture and inspect
- screenshot [full]: capture the page. `full` for the whole page. Returns the saved path.
- pdf <path>: save the page as a PDF.
- highlight <target>: mark an element on screen.
- inspect: open DevTools for the active page.

JavaScript
- evaluate <script>: run an expression in the page and return the result. Use it
for what the other actions cannot express.

## What this tool will not do

It always attaches to the browser this session already runs. It cannot start a
browser, cannot close one, cannot point at a different one, and cannot read or
write cookies, web storage, saved logins, or the clipboard. It cannot change the
viewport or intercept network traffic. Those are deliberate: the human is using
the same browser, and nothing the agent can reach may take it away or change it
under them.
