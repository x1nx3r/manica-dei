Set the session's goal, and — when the human agrees — authorize it to run unattended.

Only the root session sets a goal. A subagent works under the root's contract
and reports back; it does not call this tool.

A session can hold one run at a time. If the session already has an authorized
goal and the human is asking for a different task, call this tool with the new
goal. The tool asks the human to replace the current run. A yes resets the old
run, starts the turn counter at zero, and asks for a new authorization for the
new contract. A no keeps the current goal and its run unchanged.

Call this once, at the end of scoping, when you and the human have agreed what
the work is and how you will know it is done. Not before: the goal is the
outcome of the conversation, not its start.

Until the human authorizes it, file-editing tools are refused; reading,
searching, asking, and writing the ADR under `docs/adr/` remain available. Shell
commands still run, but a change they make before authorization is outside the
contract and will not be reviewed — do not use the shell to start the work.

- goal: the goal as you now understand it, in your words — not the human's first
  message.
- size: how big the task is — the number and blast radius of the decisions the
  task leaves undetermined. `small` (the task determines the work), `medium` (a
  few reversible decisions), `large` (many decisions, some irreversible),
  `huge` (underspecified past enumeration). Say why in `size_reason`.
- contract: the five fields. `verification` is the command that proves the
  outcome — a test, a build, a benchmark. It must be **one exact shell command
  line**: the loop runs it verbatim before every judge. Prose makes it
  unrunnable — a clause joined with a comma, or a "plus a browser check" that
  names work instead of running it, belongs in `constraints`, never here. A
  contract with no verification is refused.
- commit: `false` to write the goal and stop; `true` to ask the human to confirm
  what done means — the outcome and the check that proves it — and to authorize
  an unattended run. Authorization happens only on a yes.

When you believe the goal is met, run the verification and leave the change in
the workspace — the run is judged against the contract and the artifact, not
against your word. If the verification has not run, run it.

A `huge` goal is not one task. This tool returns a split proposal instead of
setting it — decompose it, then set the first piece.
